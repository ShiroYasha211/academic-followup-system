# نظام المتابعة الأكاديمية

نظام المتابعة الأكاديمية هو مشروع يهدف إلى تنظيم العمل الأكاديمي داخل الجامعة من خلال منصة ويب ولوحات استخدام مرتبطة بالأدوار الأساسية في البيئة الجامعية. يركز النظام على إدارة الهيكل الأكاديمي، المستخدمين، المواد، الحضور، التقارير، وطلبات تعديل الحضور بطريقة تساعد الإدارة والكوادر الأكاديمية على متابعة الطلاب بدقة.

هذا المستودع يحتوي على الواجهة الخلفية ولوحات الويب، إضافة إلى تطبيق الطالب وتطبيق الكادر الأكاديمي المبنيين باستخدام Flutter.

## الهدف من النظام

يعالج النظام مشكلة تشتت بيانات المتابعة الأكاديمية بين السجلات الورقية أو الملفات المنفصلة، ويوفر مسارًا موحدًا لإدارة:

- بيانات الكليات والتخصصات والمستويات الدراسية.
- حسابات الطلاب والدكاترة والمندوبين والمسؤولين.
- المواد وربطها بالدكاترة والمستويات.
- تسجيل حضور الطلاب ومتابعة الغياب والتأخير.
- مراجعة طلبات تعديل الحضور والحد من التعديل العشوائي.
- استخراج تقارير تساعد الإدارة على معرفة حالة الطلاب والمواد.

## الأدوار الأساسية

- مالك النظام: يمتلك صلاحيات الإدارة الكاملة ويستطيع تجهيز وضع العرض الجامعي.
- مسؤول النظام: يدير البيانات الأكاديمية والمستخدمين والتقارير.
- الدكتور: يتابع مواده وطلابه وعمليات الحضور المرتبطة به.
- المندوب: يساعد في عمليات الحضور حسب الصلاحيات الممنوحة.
- الطالب: يتابع بياناته الأكاديمية وحضوره والتنبيهات المرتبطة به.

## الميزات المعروضة للجامعة

يركز العرض الجامعي على الوظائف الأساسية التالية:

- لوحة تحكم إدارية لعرض ملخصات النظام.
- إدارة الكليات.
- إدارة التخصصات والمستويات والفصول الدراسية.
- إدارة المواد وربطها بالدكاترة.
- إدارة الطلاب والدكاترة والمندوبين.
- تسجيل ومراجعة الحضور.
- طلبات تعديل الحضور وصلاحيات التعديل.
- التقارير والإحصائيات الأكاديمية.
- سجل الأنشطة لمتابعة العمليات المهمة.
- إعدادات النظام الأساسية.

## وضع عرض مشروع التخرج

يدعم النظام وضعًا خاصًا لمالك النظام باسم `عرض مشروع التخرج`. عند تفعيله يتم تبسيط القائمة الجانبية بحيث تظهر الوظائف المناسبة للعرض الجامعي فقط، دون حذف الصفحات أو تغيير صلاحيات النظام الحقيقية.

لتجهيز وضع العرض:

1. سجّل الدخول بحساب مالك النظام.
2. افتح `إعدادات النظام`.
3. انتقل إلى `إعدادات المالك`.
4. اختر `الجامعة الافتراضية للعرض`.
5. فعّل خيار `عرض مشروع التخرج`.

بعد التفعيل:

- عند إنشاء كلية جديدة يتم ربطها تلقائيًا بالجامعة الافتراضية.
- عند إنشاء تخصص جديد تظهر كليات الجامعة الافتراضية فقط.
- يتم إخفاء الخيارات غير المطلوبة في العرض مثل خيارات العملي والسيمسترات من واجهة التخصصات.
- تبقى الصلاحيات والروابط الداخلية كما هي، والتغيير يكون في العرض فقط.

## طريقة الاستخدام داخل الجامعة

1. إعداد بيانات الجامعة:
   - يدخل مالك النظام أو المسؤول إلى لوحة التحكم.
   - يتم تحديد الجامعة الافتراضية من إعدادات المالك عند استخدام وضع العرض.

2. إنشاء الكليات:
   - من صفحة الكليات يتم إضافة الكليات المطلوبة.
   - في وضع العرض يتم ربط الكلية بالجامعة الافتراضية تلقائيًا.

3. إنشاء التخصصات:
   - يتم اختيار الكلية.
   - يتم إدخال اسم التخصص.
   - يتم تحديد عدد المستويات والفصول الدراسية.
   - يقوم النظام بإنشاء الهيكل الأكاديمي تلقائيًا.

4. إدارة المستخدمين:
   - إضافة الطلاب وربطهم بالكلية والتخصص والمستوى.
   - إضافة الدكاترة.
   - إضافة المندوبين حسب الحاجة.

5. إدارة المواد:
   - إنشاء المواد الدراسية.
   - ربط كل مادة بالدكتور والمستوى والفصل الدراسي المناسب.

6. متابعة الحضور:
   - يتم تسجيل حضور الطلاب حسب آلية الحضور المعتمدة في النظام.
   - يمكن مراجعة حالات الحضور والغياب والتأخير.
   - تظهر طلبات تعديل الحضور للمسؤول لمراجعتها ومنح الصلاحيات عند الحاجة.

7. التقارير:
   - يمكن للإدارة الاطلاع على تقارير الحضور والطلاب والمواد.
   - تساعد التقارير على تقييم الالتزام الأكاديمي واتخاذ قرارات مبنية على بيانات واضحة.

## المتطلبات التقنية

لتشغيل لوحة الويب:

- PHP 8.2 أو أحدث.
- Composer.
- MySQL أو MariaDB.
- Node.js و npm.

لتشغيل تطبيقات الجوال:

- Flutter SDK.
- Android Studio أو بيئة بناء Android.
- ملفات إعداد Firebase الخاصة بالبيئة المحلية.

## تشغيل لوحة الويب محليًا

انتقل إلى مجلد Laravel:

```bash
cd backend/student_dashboard
```

ثبّت الحزم:

```bash
composer install
npm install
```

جهّز ملف البيئة:

```bash
cp .env.example .env
php artisan key:generate
```

عدّل بيانات قاعدة البيانات داخل `.env`:

```env
DB_DATABASE=your_database
DB_USERNAME=your_username
DB_PASSWORD=your_password
```

شغّل migrations:

```bash
php artisan migrate
```

اربط ملفات التخزين:

```bash
php artisan storage:link
```

شغّل الواجهة:

```bash
npm run build
php artisan serve
```

بعدها افتح:

```text
http://127.0.0.1:8000
```

## تشغيل تطبيقات Flutter

تُشغّل تطبيقات الجوال بالإعدادات المعتمدة للمشروع.

أسماء الحزم الخاصة بالتطبيقات:

```text
تطبيق الطالب: com.academic.followup.student
تطبيق الكادر الأكاديمي: com.academic.followup.staff
```

عند استخدام Firebase يجب إنشاء تطبيقين Android بهذه الحزم، ثم وضع ملف `google-services.json` المناسب داخل مجلد Android الخاص بكل تطبيق.

لا يتم رفع هذه الملفات إلى GitHub لأنها ملفات بيئة خاصة.

تطبيق الطالب:

من داخل مجلد تطبيق الطالب:

```bash
flutter pub get
flutter run --flavor demo --dart-define=APP_VARIANT=demo
```

تطبيق الكادر الأكاديمي:

من داخل مجلد تطبيق الكادر الأكاديمي:

```bash
flutter pub get
flutter run --flavor demo --dart-define=APP_VARIANT=demo
```

بناء APK:

من داخل مجلد تطبيق الطالب:

```bash
flutter build apk --release --flavor demo --dart-define=APP_VARIANT=demo
```

من داخل مجلد تطبيق الكادر الأكاديمي:

```bash
flutter build apk --release --flavor demo --dart-define=APP_VARIANT=demo
```

استخدم أوامر التشغيل والبناء كما هي لضمان ظهور اسم النظام وإعداداته المعتمدة.

آلية عمل النظام

يعتمد النظام على هيكلية Client/Server، حيث تتصل جميع التطبيقات بواجهة برمجة التطبيقات (API) المبنية باستخدام Laravel، بينما تُخزن جميع البيانات داخل قاعدة بيانات مركزية.

تسلسل العمل داخل النظام يكون كالتالي:

1. يقوم مالك النظام أو مسؤول النظام بإعداد البيانات الأساسية مثل الكليات، والتخصصات، والمستويات، والفصول الدراسية.
2. يتم إنشاء حسابات المستخدمين وإسناد الأدوار المناسبة لكل مستخدم (طالب، دكتور، مندوب، مسؤول).
3. تُنشأ المواد الدراسية ويتم ربطها بالدكاترة والمستويات والفصول الدراسية.
4. يسجل الطلاب الدخول إلى تطبيق الطالب لمتابعة بياناتهم الأكاديمية، وجدولهم الدراسي، وسجل الحضور والتنبيهات.
5. يسجل أعضاء الكادر الأكاديمي الدخول إلى تطبيق الكادر لتسجيل حضور الطلاب وإدارة العمليات المسموح بها حسب الصلاحيات.
6. تنتقل جميع عمليات الحضور مباشرة إلى الخادم، حيث يتم حفظها والتحقق منها وإتاحتها للإدارة.
7. في حال وجود خطأ في تسجيل الحضور، يمكن إرسال طلب تعديل ليتم مراجعته من قبل المسؤول واعتماده أو رفضه.
8. تعرض لوحة التحكم جميع البيانات والإحصائيات والتقارير بصورة لحظية، مما يساعد الإدارة على متابعة الأداء الأكاديمي واتخاذ القرارات المناسبة.

مكونات النظام

يتكون النظام من أربعة أجزاء رئيسية:

- لوحة التحكم (Web Dashboard): مخصصة لإدارة النظام والبيانات الأكاديمية وإعداد التقارير.
- واجهة برمجة التطبيقات (API): مسؤولة عن استقبال الطلبات من التطبيقات وإدارة البيانات.
- تطبيق الطالب: يتيح للطالب متابعة بياناته الأكاديمية والحضور والإشعارات.
- تطبيق الكادر الأكاديمي: يتيح للدكاترة والمندوبين تسجيل الحضور وإدارة العمليات المرتبطة بالمواد الدراسية.

جميع هذه المكونات تعمل معًا على قاعدة بيانات موحدة لضمان تزامن البيانات بين جميع المستخدمين.
