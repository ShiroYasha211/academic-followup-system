# التوثيق التقني لنظام المتابعة الأكاديمية

## البنية العامة

يتكون النظام من عدة طبقات مترابطة:

- تطبيق الطالب.
- تطبيق الكادر الأكاديمي.
- لوحة إدارة ويب.
- واجهة API.
- قاعدة بيانات مركزية.
- خدمات إشعارات وتنبيهات.

يتم فصل واجهات المستخدم عن منطق الخادم، بحيث تتعامل التطبيقات مع البيانات عبر API موحدة، بينما تتولى لوحة الإدارة ضبط البيانات والصلاحيات.

## تطبيق الطالب

تطبيق الطالب مبني بواجهة مخصصة للطلاب، ويعتمد على تسجيل الدخول وجلب بيانات الطالب من الخادم.

### أهم الوحدات

- المصادقة وتسجيل الدخول.
- الصفحة الرئيسية.
- المقررات الدراسية.
- الجدول الدراسي.
- جداول الاختبارات.
- مصادر المقرر.
- التكليفات والواجبات.
- التذكيرات.
- المكتبة المشتركة.
- الأخبار والإعلانات.
- التنبيهات.
- الرسائل.
- استفسارات الدكتور.
- الكويزات.
- النجوم.
- QR للحضور.

## تطبيق الكادر الأكاديمي

تطبيق الكادر يستخدمه أكثر من دور، وتظهر الوظائف حسب صلاحية المستخدم.

### وضع الدكتور

يشمل:

- الحضور.
- أعذار الغياب.
- التكليفات.
- الدرجات.
- التقارير.
- استفسارات الطلاب.
- الإعلانات.
- الكويزات.
- النجوم.
- المكتبة المشتركة.
- الرسائل.
- الأخبار.
- الإشعارات.

### وضع المسؤول الإداري

يشمل:

- إدارة الطلاب.
- إدارة الدكاترة.
- إدارة المندوبين.
- إدارة التخصصات.
- إدارة المواد.
- جداول الاختبارات.
- الجداول الدراسية.
- إعدادات الكلية.
- الأعذار.
- إشعارات الكلية.
- التقارير.

## لوحة الإدارة الخلفية

لوحة الإدارة تعمل كواجهة مركزية لإدارة البيانات الأساسية للنظام، وتستخدم لضبط:

- الحسابات.
- الصلاحيات.
- البيانات الأكاديمية.
- الجداول.
- المواد.
- الإشعارات.
- التقارير.
- إعدادات النظام.

## واجهة API

تعمل API كطبقة وسيطة بين التطبيقات وقاعدة البيانات.

### مسؤوليات API

- استقبال طلبات التطبيقات.
- التحقق من هوية المستخدم.
- تطبيق الصلاحيات.
- جلب البيانات من قاعدة البيانات.
- حفظ التعديلات.
- إرسال الردود بصيغة مناسبة للتطبيقات.
- دعم الإشعارات والعمليات المرتبطة بها.

## إدارة الصلاحيات

يعتمد النظام على دور المستخدم لتحديد ما يمكنه الوصول إليه.

### أمثلة على الصلاحيات

- الطالب يرى بياناته فقط.
- المندوب يرى بيانات الدفعة أو النطاق المرتبط به.
- الدكتور يرى المواد والطلاب المرتبطين به.
- المسؤول الإداري يرى بيانات الكلية أو النطاق الإداري.

هذا الفصل يقلل من أخطاء الوصول غير المصرح به، ويجعل كل واجهة تعرض فقط ما يحتاجه المستخدم.

## الإشعارات

يدعم النظام الإشعارات لتنبيه المستخدمين بالأحداث المهمة مثل:

- إعلان جديد.
- تكليف جديد.
- تحديث في الحضور أو الغياب.
- رسالة جديدة.
- إشعار من الكلية.
- تنبيهات مرتبطة بالكويزات أو الجداول.

تظهر الإشعارات داخل التطبيق، ويمكن ربطها بإشعارات الهاتف حسب الإعدادات والخدمات المفعلة.

## الكويزات والحماية

يدعم النظام كويزات مرتبطة بالمواد، ويشمل ذلك:

- إنشاء كويز من جهة الدكتور.
- تحديد إعدادات الاختبار.
- دخول الطالب للكويز من التطبيق.
- مؤقت أثناء الاختبار.
- تسليم الإجابات.
- عرض النتيجة حسب إعدادات الدكتور.

كما يتضمن النظام إجراءات حماية أساسية أثناء الاختبار، مثل تقليل فرص الخروج أو التحايل أثناء أداء الكويز حسب قدرات التطبيق والنظام.

## الحضور

يدعم النظام تسجيل الحضور بعدة آليات، منها:

- رصد الحضور من جهة الدكتور أو المندوب.
- جلسات QR للحضور.
- متابعة السجلات.
- ربط الحضور بالمادة والمحاضرة.
- متابعة إنذارات الغياب.

## التقارير

توفر التقارير ملخصات إدارية وأكاديمية تساعد على فهم الحالة العامة، مثل:

- تقارير المواد.
- تقارير الحضور.
- تقارير الغياب والإنذارات.
- تقارير الدفعات.
- تقارير أداء الكادر.

## التخزين والاتصال

يعتمد النظام على خادم مركزي وقاعدة بيانات، وتقوم التطبيقات بجلب البيانات عند الحاجة. كما يمكن أن تعرض بعض الواجهات مؤشرات اتصال أو تحديث عند استعادة الاتصال، مما يحسن تجربة المستخدم عند ضعف الشبكة.

## قابلية التوسع

تم تصميم النظام ليقبل التوسع مستقبلاً من خلال:

- إضافة أدوار جديدة.
- إضافة وحدات أكاديمية جديدة.
- توسيع التقارير.
- تحسين التكامل مع الأنظمة الجامعية.
- دعم خصائص إضافية للإشعارات والتحليلات.

## التقنيات المستخدمة

يعتمد النظام على تقنيات حديثة مناسبة للتطبيقات الأكاديمية:

- Flutter لتطبيقات الهاتف.
- Laravel للواجهة الخلفية وواجهة API.
- MySQL لقاعدة البيانات.
- Firebase أو خدمات مشابهة للإشعارات عند التفعيل.
- واجهات REST API لربط التطبيقات بالخادم.
